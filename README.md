# 求职证据审计与模拟面试工作台

本项目是一个单机、自托管的中文 AI 应用：它会核验简历既有主张与项目材料之间的支持关系，经用户逐条确认后生成岗位匹配报告，并提供文字版模拟面试与复盘。

当前已提供健康检查、模型初始化向导、任务创建与材料导入、BM25 + RRF 候选证据召回、逐条证据审计，以及审核完成后的岗位匹配与证据审计报告（支持 UTF-8 Markdown 导出）。报告生成后可开始文字版多轮模拟面试；系统一次只展示一题，回答后给出下一题或追问，主动结束后才生成统一复盘。

## 技术栈与关键设计

- **界面**：React、TypeScript、Vite；按材料、审计、报告、面试阶段展示状态与操作入口。
- **服务与约束**：Python 3.12+、FastAPI、Pydantic；校验请求、模型结构化输出及任务内引用白名单。
- **证据检索**：SQLite FTS5 BM25 + RRF，融合原查询与标签同义变体的关键词排名；没有向量检索或神经 Reranker。
- **流程与恢复**：LangGraph 组织审计和出题节点；自定义 SQLite 检查点、持久化会话、请求幂等与操作租约处理恢复及重复请求。审计图未配置 LangGraph 原生 checkpointer。
- **本地交付**：Docker Compose；业务数据和模型配置分别挂载到宿主机目录，应用由容器提供前后端页面。

设计边界：人工接受不改变证据支持度；代码存在不证明个人贡献；面试复盘用于练习，不认证能力或经历真实性。模型失败时保留已提交回答，明确提示重试，不把格式可解析的残缺内容保存为完整复盘。

## 快速体验

推荐按下方 Docker Compose 步骤初始化服务，再使用 [`examples/`](examples/) 中的虚构材料：创建任务 → 导入简历、JD 和项目目录 → 提取并逐条审核主张 → 生成 Markdown 报告 → 开始面试 → 作答并生成复盘 → 刷新检查记录与引用。

不需要接入真实求职资料，也不需要 GitHub 访问权限。模型连接测试、证据判定和面试生成可能产生 API 费用；未配置可用模型时不能把页面或健康检查正常当作完整功能验收。页面面向桌面使用，不是移动端优先布局。

## 雾蓝工作台导航

配置通过后会进入桌面优先的雾蓝工作台（最低宽度 1024px）。左侧导航按业务阶段组织，阶段未满足时会显示锁定原因，而不是隐藏入口：

1. **任务概览**：显示材料数量、能力主张、待审核队列和唯一的下一步操作。
2. **材料中心**：支持批量文件、项目目录和粘贴文本导入；材料就绪后可提取能力主张。
3. **证据审计**：用可横向滚动的表格选择主张，在详情面板查看候选证据、支持度、门禁和审核动作。
4. **审计报告**：完成全部主张审核后解锁，可生成并下载 Markdown 报告。
5. **模拟面试**：报告生成后解锁；默认综合模式直接开始，高级设置可调整题数、时长和侧重点。

使用同一浏览器、同一访问地址刷新页面时，会自动打开最近一次任务的概览，并从后端任务快照恢复材料、主张、模型判定、门禁、审核状态与报告就绪状态。浏览器 localStorage 只记录任务编号，不保存材料正文或 API Key；禁用或清除后，后端任务数据不会删除。新版面试通过后端恢复题号、问答和已保存复盘，不因进入页面自动调用模型。未提交面试草稿及请求键使用按任务/会话/回合隔离的 sessionStorage；关闭浏览器会话不保证草稿恢复。禁用存储时仅保留页面内存，其他未提交表单不保证恢复。

## 本地开发

前提：Python 3.12+、Node.js 22 和 npm。以下为 Windows PowerShell 示例，在项目根目录执行；Python 包使用清华 PyPI 镜像，npm 使用 npmmirror，不要求固定磁盘路径。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]" --index-url https://pypi.tuna.tsinghua.edu.cn/simple
npm --prefix frontend ci --registry=https://registry.npmmirror.com
npm --prefix frontend run build
.\.venv\Scripts\uvicorn.exe job_evidence_agent.app:app --host 127.0.0.1 --port 8001
```

访问 <http://127.0.0.1:8001>。后端会提供已构建的 `frontend/dist`，页面和 `/api` 使用同一来源。单独运行 Vite 的 `npm run dev` 不会自动把请求转发到后端，当前配置没有 API 代理；这里推荐同源构建方式，不假设两端独立启动就能联通。

上述首次启动建立业务库后，在服务终端按 Ctrl+C 停止，再初始化新版面试表：

```powershell
.\.venv\Scripts\python.exe -m job_evidence_agent.migrate_interviews --database data/workbench.sqlite3 --backup-dir data/backups
.\.venv\Scripts\uvicorn.exe job_evidence_agent.app:app --host 127.0.0.1 --port 8001
```

迁移会先备份并检查业务库，数据库不存在时会拒绝创建空库；不要将它指向不相关的数据库。后端测试命令为 `.\.venv\Scripts\python.exe -m pytest`，更多说明见 [部署、初始化与数据恢复](docs/deployment.md)。

## Docker Compose 启动

### 本机一键启动：Career Studio

开发者本机已有部署，可双击项目根目录或桌面上带专属图标的 **Career Studio** 快捷方式；备用入口为 `Career Studio.cmd`。启动器会检查 Docker，引擎未就绪时自动调用本机预配置的 Docker 启动入口，再启动本项目已有的 `app` 容器，等待健康接口和网页响应后打开浏览器。访问地址取自容器的实际本机端口，默认是 `http://127.0.0.1:8001`。快捷方式、启动器和图标保留本地，不随公共仓库发布；其他电脑请使用下方标准 Compose 命令。

日常启动只启动已有容器，不重建镜像、不替换容器、不执行数据库迁移，沿用已部署的数据和模型配置。首次安装或容器已被删除时会提示按下方部署说明处理。首次等待 Docker 最多 3 分钟，网页就绪最多 2 分钟；失败时窗口保留提示。启动成功后窗口自动关闭，关闭浏览器不会停止服务。

图标位于 `assets/career-studio.ico`，矢量源文件为 `assets/career-studio.svg`。快捷方式绑定当前项目路径；迁移项目或 Docker 安装目录后需要调整快捷方式目标、图标路径或 `scripts/start-project.ps1` 中的 Docker 路径。此入口仅改变本机启动体验，网页内产品名称不变。

### 首次安装与手动启动

前提：Docker Engine / Docker Desktop 已启动，支持 `docker compose`。基础镜像使用 DaoCloud 镜像加速，首次构建需要网络。仅新安装按以下顺序操作，已有运行数据的升级先读部署文档：

```powershell
docker compose up -d --build
docker compose ps
```

启动后访问 <http://127.0.0.1:8001>，健康检查地址为 <http://127.0.0.1:8001/api/health>。如需改用其他未占用端口，请在启动前设置 `JOB_EVIDENCE_PORT`。

首次健康检查成功、业务库建立后，停止应用并初始化新版面试表，再恢复服务：

```powershell
docker compose stop app
docker compose run --rm --no-deps app python -m job_evidence_agent.migrate_interviews --database /app/data/workbench.sqlite3 --backup-dir /app/data/backups
docker compose up -d --no-build app
```

新版面试表需显式初始化，应用启动不会自动迁移已有数据。首次启动或升级后，在开启面试前按 [部署、初始化与数据恢复](docs/deployment.md) 备份并执行迁移；未初始化时面试接口返回 503，其他业务不因此重置。迁移失败时不要继续后续启动命令或删除数据库，应保留错误和备份后排查。

Docker 会在项目根目录创建 `data/` 与 `runtime-config/`。其中会保存运行数据和本机模型配置，均已被 Git 忽略；不要提交真实简历、项目源码快照或 API Key。

如需进行一次不影响已有数据的全新验收，可使用独立目录：

```powershell
$env:JOB_EVIDENCE_DATA_DIR = ".acceptance-data"
$env:JOB_EVIDENCE_CONFIG_DIR = ".acceptance-runtime-config"
docker compose up --build
```

验收结束后可执行 `docker compose down` 停止容器；不会删除这两个运行目录。若要删除它们会丢失其中的任务和本机模型配置，请先自行确认不再需要。

首次访问页面时需要填写 Base URL、模型名和 API Key。系统会在“测试连接”与“保存并进入工作台”时各向 OpenAI 兼容的 `/chat/completions` 接口发起一次极短请求；第二次校验通过后，配置才会写入 `runtime-config/model.env`。

`runtime-config/model.env` 包含可用的 API Key，因此它只应保留在自己的本机磁盘中，不应上传到 Git、网盘或发送给他人。接口状态和页面均不会回显 API Key。

## 材料导入范围与限制

创建任务后，可以在同一任务下多次导入简历、岗位描述和多个项目目录的材料，也可以直接粘贴文本。支持 Markdown、TXT、DOCX、可复制文本 PDF，以及常见项目说明和源码文本（如 `pyproject.toml`、`package.json`、`Dockerfile`、`.py`、`.ts`、`.tsx`）。

为防止误上传敏感或无关内容，系统会跳过 `.env`、`.git`、`node_modules`、虚拟环境、缓存目录、图片和其他二进制文件；目录导入只保存相对路径，不保存本机绝对路径。当前限制为单次最多 200 个文件、单文件不超过 2 MB、单次可入库文本总量不超过 10 MB。扫描件或无可复制文本的 PDF 会被拒绝并提示改用可复制文本或粘贴内容。

## 审计、恢复与隐私边界

1. 导入简历后点击“生成待审核主张”；系统只从简历材料抽取主张，不会从项目文件新增经历。
2. 开始逐条审核后，点击“运行候选证据判定”。系统用 FTS5 BM25 + RRF 从项目材料与补充说明找出候选片段，简历和 JD 不作为能力证明进入候选。仅将当前主张和候选片段发送给已配置的模型；没有候选时直接返回没有证据，不调用模型。
3. 模型只给出材料支持度；确定性门禁负责决定是否“证据充分”。代码或 README 的存在不能单独证明用户本人负责过该工作。
4. 审核中断后刷新页面或重启应用，重新打开同一任务即可从当前待审核主张继续。`data/workflow.db` 是本机恢复所需的 checkpoint 文件。
5. 在逐条审核页面接受尚未判定或有风险的主张时，必须二次确认；人工接受不改变支持度或门禁。误接受或误拒绝后，可选择该条主张，点击“撤销审核，返回待审核”并确认：保留材料、证据判定及历史记录，将该条放回当前审核位置，其余待审核条目继续排队。已生成报告的任务暂不允许撤销，避免与报告/面试状态不一致。

充分支持必须引用项目材料；仅引用补充说明最多为部分支持，没有引用的支持结论会被后端降为没有证据。材料类型不能证明内容真实或本人贡献，项目文件中的重复自述仍需模型与人工核验。旧判定不会自动改写；当前待审核主张可以手动点击“重新判定当前主张”，替换该条支持度和门禁，不改变人工审核状态。

模型配置、导入材料、SQLite 数据库和工作流 checkpoint 都在本机挂载目录保存；这不等于材料不出网。审计与面试调用会把选中的主张、材料、JD 和回答文本发送给用户配置的模型服务商；请按其隐私政策处理个人信息并先脱敏。系统不会自动读取 GitHub、执行项目代码/Shell、发送邮件、爬取招聘网站或对外投递。

## 模型驱动文字面试（版本 2）

先生成报告且至少人工接受一条主张。人工接受不等于事实已验证；风险随主张传入模型。默认 5 题，高级设置为 1–10 题、最多 5 项重点（每项 100 字）和 5–120 分钟预计时长；预计时长不是倒计时。一次只问一题，主问题后最多连续追问一次同主题，再轮转；追问计入题数，题数有限不保证覆盖所有主张。程序确定话题与引用边界，模型生成自然语言问题，不再拼接材料作为模板。

- 回答最多 2,000 字。面试中不评分、不展示答案建议；末题答完进入待结束状态。提前结束需要确认；零回答不调用复盘模型，也不生成能力评价。
- 结束后持久化整轮复盘：逐题原回答、有效信息、遗漏、技术解释、改进建议、四类总结与未覆盖主张。技术结论是模型分析，不是代码执行验证或招聘结论。回答不会写入审计证据或改变人工审核结果。
- 正常完成 N 题约为 N 次出题调用 + 1 次复盘调用。每项生成操作最多两次 HTTP 请求，格式修正与 JSON 模式回退共用预算。超时、鉴权、限流不自动盲重发；手动重试可能额外计费，不能保证服务商计费恰好一次。usage 仅记录服务商已返回的数值，可能不完整，不用于估算价格。
- 下一题失败时回答已保存，只需重试生成；刷新状态只是 GET，不调用模型。网络失败时保留草稿与请求键；原内容可直接重试，改内容前先刷新确认是否已保存，已保存回答不能覆盖。同任务只允许一个未结束新版会话。
- 每条主张最多 3 段证据，每段 1,200 字；JD 最多 4,000 字；提问输入最多 20,000 字、复盘最多 30,000 字（字符预算不是 Token 上限）。缩减证据或早期历史会提示；必要信息仍超限则明确失败，不静默丢弃最新回答。出题/复盘输出上限分别为 1,000/6,000 Token，截断结果不保存为成功。
- 开始时冻结上下文，只引用本任务合规项目/补充材料；简历和 JD 不能当独立能力证据。旧版模板面试为版本 1，只读查看原题与回答；未保存过的复盘不补造，新一轮需明确点击开始。

### 报告如何解释审核结果

全部主张审核完成后生成报告，不额外调用模型。报告和 Markdown 按条展示人工接受/拒绝、证据支持度、风险、判定理由、门禁与引用定位，并为 Docker 编排、Kubernetes、性能优化等材料不足项提供补证建议。人工接受不等于证据充分；已拒绝的主张也保留在报告中，但不计入已接受能力。

历史判定引用中的简历、JD、缺失或跨任务片段不会作为报告证据展示，会标明历史引用风险；原判定与审核记录不改写。证据摘要最多展示 600 字，常见密钥字面量与 Windows 本机绝对路径会脱敏，但这不等于完整的自动隐私审查，分享前仍需自行检查。

岗位覆盖为关键词规则初筛：保留岗位条目与定位，关联简历主张，区分已接受但待补证、仅有已拒绝主张、未关联与待人工分析。它不是语义匹配模型，不输出匹配率，也不认证某条岗位要求已完整满足。未导入 JD 时明确提示无法分析。

## 测试与故障排查

```powershell
# 后端全部测试
.\.venv\Scripts\python.exe -m pytest

# 前端测试与生产构建
npm --prefix frontend run test
npm --prefix frontend run build
```

- 页面停留在初始化界面：检查 Base URL、模型名和 API Key，先点击“测试连接”。
- 模型判定失败：根据页面提示区分 API Key/模型权限、Base URL/模型名、限流/额度、超时和输出格式问题。判定失败不会保存新的审计结论，也不会自动接受主张；可以在当前主张上重试，无需重新创建任务。
- 结构化输出兼容：审计请求明确要求 `verdict`、候选证据 ID 整数数组 `links` 和非空说明 `rationale`。服务明确不支持 JSON 模式时，会移除 `response_format` 再试一次，但仍严格校验输出与候选引用；格式失败时仅增加一次纠正提示。两种重试共享最多 2 次请求的预算，网络、鉴权、限流和服务端错误不盲目重试。
- 导入文件被跳过：检查是否为 `.env`、依赖目录、图片/二进制，或是否超过大小限制；这些限制是为避免泄露敏感文件。
- Docker 端口被占用：启动前设置其他 `JOB_EVIDENCE_PORT`，例如 `$env:JOB_EVIDENCE_PORT = "8011"`。
