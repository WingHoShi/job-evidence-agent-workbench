# Job Evidence Agent Workbench

**从简历主张核验到模拟面试的本地求职准备工作台**

把简历、岗位描述和项目材料放进同一个任务，逐条核对证据、整理待补充信息，再围绕项目进行问答练习与引用复盘。

## 项目简介

简历里写了“使用 Docker Compose 编排服务”，项目目录里却只有接口代码：**哪些内容已有材料支持，哪些还缺配置、日志或实现细节？** 面试准备也不应停留在通用题库，而需要回到简历中的具体项目。

求职证据审计与模拟面试工作台将这两件事串成一条流程：先从简历提取能力主张，检索项目材料并逐条审核，再生成带引用的报告，最后围绕已接受的主张开展文字面试与整轮复盘。它不从项目文件中新增经历，也不替用户编造回答。

应用面向**单用户、本地自托管、桌面浏览器**，接入用户自备的 OpenAI-compatible 模型服务。资料和业务状态保存在本机，模型调用时会发送所需的材料片段与回答。

## 功能介绍

### 简历、岗位与项目材料集中管理

按求职目标创建独立任务，导入简历、JD、项目目录或粘贴文本。支持 Markdown、TXT、DOCX、可复制文本 PDF 和常见源码文本；目录导入跳过 `.env`、`.git`、依赖目录及二进制文件，只保留相对路径。

工作台按“材料 → 审计 → 报告 → 面试”组织操作，未满足条件的阶段会说明解锁原因，减少在多个页面间寻找下一步的成本。

### 逐条核验简历主张

从简历既有表述生成待审核主张，用 **SQLite FTS5 BM25 + RRF** 召回相关项目片段。详情中可查看候选原文、定位、模型判定理由、证据支持度与门禁结果，而不是只得到一个笼统分数。

模型负责分析材料支持关系，程序负责校验结构与引用范围；人工逐条接受、拒绝或在允许阶段撤销审核。**人工接受与证据支持度分别记录**，接受风险主张不会自动把材料不足变成证据充分。

### 带引用的审计与岗位报告

完成主张审核后生成报告，并支持 **Markdown 导出**。报告保留人工决定、材料支持度、风险、引用定位和补证建议，让“写了什么、有什么依据、还缺什么”可以对照查看。

岗位描述用于关键词规则初筛，提示已关联与尚待分析的要求，不输出看似精确的岗位匹配率。报告汇总不额外调用模型。

### 围绕项目的一题一答面试

报告生成且至少接受一条主张后，可开始文字模拟面试。默认 5 题，高级设置可调整题数、侧重点与预计时长；**一次只展示一题**，根据回答生成后续问题或同主题追问。

面试过程中不展示评分和参考答案，结束后再统一复盘。程序约束主题轮转、追问次数和材料引用范围，避免把一次练习变成无边界的连续追问。

### 整轮复盘与原文引用

复盘保留逐题问题与原回答，整理有效信息、表达遗漏、技术解释和改进建议，并汇总回答前后一致性、简历主张对照、技术缺口与下一步学习方向。

逐题内容可折叠查看，引用材料集中展示，点击分析中的引用编号可定位并展开原文。面试回答不会反过来充当审计证据，也不会改变此前的人工审核结果。

### 进度恢复与失败后继续

任务、审计状态、已提交回答和已保存复盘持久化到本地 SQLite。刷新后可重新打开任务；下一题生成失败时保留已提交回答，用户只需显式重试生成，而不是重新提交答案。

重复请求由后端幂等校验和操作租约约束。模型结构错误、引用越界或复盘截断会明确报错，不把“能解析的残缺 JSON”当作完整结果保存。

## 技术设计

- **前端交互**：React + TypeScript + Vite，按业务阶段呈现材料、审核、报告、面试和复盘。
- **应用接口**：Python + FastAPI + Pydantic，校验请求、模型结构化输出与任务内引用白名单。
- **候选证据召回**：SQLite FTS5 BM25，融合原查询与标签同义变体的关键词排名，再通过 RRF 合并候选；当前没有向量检索或神经 Reranker。
- **流程编排**：LangGraph 组织审计和出题节点，程序规则控制流程与引用边界，模型生成分析或问题，不要求每个节点都调用模型。
- **状态与并发**：自定义 SQLite 检查点、持久化面试会话、幂等请求与操作租约，处理刷新恢复、重复提交和生成失败。审计图未配置 LangGraph 原生 checkpointer。
- **本地交付**：Docker Compose 提供同源前后端，业务数据与模型配置分别挂载到宿主机目录。

三个关键取舍：

1. **检索材料与事实认证分开**：只从简历提取主张，简历和 JD 不作为独立能力证据；代码存在也不能单独证明个人贡献。
2. **模型分析与人工决定分开**：模型给出支持度，确定性门禁校验证据，人工记录接受或拒绝，三者不相互覆盖。
3. **回答提交与模型生成分开**：先保存回答，再生成下一题；失败后可以继续，引用校验与截断检查通过后才保存完整复盘。

## 快速开始

### 1. 安装并打开 Docker Desktop

Windows 用户先按 [Docker 官方安装说明](https://docs.docker.com/desktop/setup/install/windows-install/) 安装 Docker Desktop，完成 WSL 2 / 虚拟化配置并等待 Linux 容器引擎就绪。其他系统需要可用的 Docker Engine 和 Compose。

下载仓库并解压，或使用 Git 克隆。在项目根目录打开终端，首次构建启动：

```powershell
docker compose up -d --build
docker compose ps
```

首次需要下载依赖和构建镜像。等待 <http://127.0.0.1:8001/api/health> 可访问后，再进行下一步。已有数据的升级请先看 [部署与恢复说明](docs/deployment.md#有数据的升级)，不要照搬首次安装流程。

### 2. 首次初始化面试表

服务建立业务库后，**先停止应用**，执行面试表初始化；该命令会先检查并备份业务库：

```powershell
docker compose stop app
docker compose run --rm --no-deps app python -m job_evidence_agent.migrate_interviews --database /app/data/workbench.sqlite3 --backup-dir /app/data/backups
```

**仅在初始化成功后**恢复服务：

```powershell
docker compose up -d --no-build app
```

应用不会自动迁移已有数据库；未初始化时面试接口会提示不可用。初始化失败时保留错误和备份，不继续启动命令或删除数据库。已完成初始化的日常使用无需重复执行。

### 3. 配置自己的模型 API

打开 **<http://127.0.0.1:8001>**，在初始化页面填写 Base URL、模型名和自己的 API Key。服务需兼容 `/chat/completions` 接口；项目不提供公共密钥或共享额度。

“测试连接”和“保存并进入工作台”**分别会发送一次短请求，可能计费**。配置保存在本机 `runtime-config/model.env`，不回显密钥、不随仓库发布；文件仍包含明文密钥，不要分享、截图或上传。

### 4. 用虚构材料走完流程

先使用仓库中的 [虚构简历](examples/resume.md)、[岗位描述](examples/jd.md) 和 [示例项目](examples/projects/)，无需上传真实求职资料：

创建任务 → 导入材料 → 提取主张 → 逐条判定与人工审核 → 生成报告 → 开始面试 → 结束并查看引用复盘。

日常启动可执行 `docker compose up -d --no-build app`。详细操作、恢复规则和常见问题见 [使用指南](docs/usage.md)；原生开发、端口调整和数据备份见 [运行与部署指南](docs/deployment.md)。

## 使用边界

- **本地存储不等于资料不出网**：模型分析与面试会把选中的主张、材料、JD 和回答发送给你配置的服务商，使用前先确认资料允许发送。
- **材料支持不等于经历认证**：报告与复盘帮助整理证据和练习表达，不认证能力、材料真实性或个人贡献，也不保证模型结论无误。
- **单用户本机使用**：没有公网多租户鉴权，不要直接暴露服务；界面面向桌面浏览器，不是移动端优先设计。
- **只读分析项目文本**：不会自动读取 GitHub、执行导入的代码或 Shell，也不会爬取招聘网站、发送邮件或自动投递。扫描 PDF 不提供 OCR。
- **分享前检查隐私**：配置、导入材料、数据库、备份和导出报告可能包含敏感信息；跳过规则与脱敏处理不能替代人工检查。
