# 求职证据审计与模拟面试工作台

**先核对简历依据，再围绕自己的项目练面试。**

导入简历、岗位描述和项目资料，逐条检查材料支持情况，整理报告，并通过一题一答和整轮复盘发现准备盲点。

## 适合用来做什么

- **检查简历是否有据可讲**：简历中的一项能力，能否找到对应的代码、配置或项目说明？还需要补充什么材料？
- **按目标岗位梳理准备重点**：把岗位要求与简历内容放在一起，查看已关联的内容和仍需准备的部分。
- **围绕自己的项目练面试**：基于导入的项目资料回答问题，结束后对照原回答和材料复盘，而不是只刷通用题库。

应用在自己的电脑上运行，适合单人使用。需要自行配置模型 API，不提供公共密钥或共享额度。建议使用桌面浏览器打开。

## 功能介绍

### 集中管理求职材料

按求职目标创建任务，分别导入简历、岗位描述和项目材料。支持多选文件、选择项目目录或粘贴文本，可读取 Markdown、TXT、DOCX、可复制文本 PDF 和常见源码文本。

选择目录时会跳过密钥配置、依赖目录和二进制文件；导入前仍需自行检查敏感内容。资料按任务管理，方便围绕不同岗位分别准备。

### 逐条查看简历依据

从简历提取已经写出的能力与经历表述，为每一条查找相关项目材料。你可以对照原文、查看支持程度和判定理由，再决定接受、拒绝或补充材料。

**你的审核决定与材料支持程度分别保留。** 即使人工选择接受，材料不足的提醒也不会因此消失。项目文件只用于核验，不会被用来自动新增经历。

### 查看报告与岗位对照

审核完成后生成报告，汇总每条表述的人工决定、材料依据、风险和补充建议，并支持下载为 Markdown 文件。

导入岗位描述后，还可查看岗位要求与简历内容的关联情况。岗位对照只用于辅助梳理，不提供岗位匹配率，也不替代实际招聘判断。

### 一次一题的项目面试

生成报告并至少接受一条简历表述后，即可开始文字面试。默认 5 题，可在高级设置中调整题数、侧重点和预计时长。

系统一次展示一题，并根据回答继续提问或追问。练习过程中不展示评分或参考答案；答完后主动结束，再统一查看复盘。预计时长仅作参考，不是倒计时。

### 对照原回答和引用复盘

复盘保留每题问题与原回答，指出表达遗漏、需要补充的技术知识和下一步建议。题目详情可以折叠，引用编号可以点击并展开对应原文，方便核对分析依据。

已提交回答和已保存复盘会保留在本机。下一题生成失败时，不必重新提交已保存的回答，可按页面提示重试生成。面试回答不会反过来成为经历证明，也不会改变此前的审核决定。

## 快速开始

以下为首次安装步骤。已安装且有任务数据的用户，不要删除数据目录或重复初始化来排查问题。

### 1. 安装并打开 Docker

Windows 用户先按 [Docker Desktop 官方安装说明](https://docs.docker.com/desktop/setup/install/windows-install/) 完成安装和必要的 WSL 2 / 虚拟化配置。打开 Docker Desktop，等待 Linux 容器引擎就绪。其他系统需要可用的 Docker Engine 和 Compose。

下载本仓库并解压，或使用 Git 克隆。在项目根目录打开终端，运行：

```powershell
docker compose up -d --build
docker compose ps
```

首次需要下载依赖和构建应用，耗时取决于网络。确认 <http://127.0.0.1:8001/api/health> 能显示状态信息，再进行下一步。

### 2. 完成首次初始化

这一步用于启用模拟面试，只需在首次安装时完成。先停止应用，再运行初始化命令；命令会先检查并备份已有业务数据：

```powershell
docker compose stop app
docker compose run --rm --no-deps app python -m job_evidence_agent.migrate_interviews --database /app/data/workbench.sqlite3 --backup-dir /app/data/backups
```

**仅在命令成功后**继续：

```powershell
docker compose up -d --no-build app
```

如果初始化失败，保留报错和备份，先排查原因，不继续后续启动命令，也不要删除数据库。日常启动无需重复初始化。

### 3. 填写自己的模型 API

打开 **<http://127.0.0.1:8001>**，按初始化页面填写：

- **Base URL**：模型服务商提供的接口基础地址，需兼容 OpenAI 的聊天接口。
- **模型名称**：自己账户实际有权调用的模型。
- **API Key**：自己在服务商平台申请的密钥。

“测试连接”和“保存并进入工作台”分别会发送一次短请求，**可能产生费用**。审核材料、生成面试题和复盘也会消耗自己的 API 额度；网页订阅或其他 Coding Plan 不保证可用于这里。

密钥不在页面回显，保存在本机 `runtime-config/model.env`。它仍是明文秘密文件，不要分享、截图或上传。

### 4. 开始第一轮准备

可以先使用仓库中的 [虚构简历](examples/resume.md)、[岗位描述](examples/jd.md) 和 [示例项目](examples/projects/)，不必上传真实个人资料：

创建任务 → 导入材料 → 提取简历表述 → 逐条判定与人工审核 → 查看报告 → 开始面试 → 结束并查看复盘。

日常使用时，先打开 Docker Desktop，再在原项目目录执行：

```powershell
docker compose up -d --no-build app
```

然后访问 <http://127.0.0.1:8001>。关闭浏览器不会停止后台服务。

## 常见问题

**为什么不能开始面试？**

需要先完成材料审核、生成报告，并至少接受一条简历表述。如果页面提示未初始化，请检查首次初始化是否成功；不要删除已有任务来解决。

**模型连接失败怎么办？**

检查接口地址、模型名称、密钥权限、账户额度和网络，按页面错误提示处理。重新测试连接可能计费，不要连续重复点击。

**模型认为材料不足，是不是说明这项经历是假的？**

不是。它只表示当前提供的材料不足以支持这条表述。可以补充相关配置、实现说明或运行记录，再重新判定；代码存在也不能单独证明本人贡献。

**刷新或生成失败后，原回答还在吗？**

已提交回答和已保存复盘保存在后端，重新打开同一任务可继续查看。未提交草稿不保证在关闭浏览器会话后恢复；生成失败时先刷新状态，确认回答是否已保存，再按页面提示重试。

**哪些文件不能导入？**

扫描 PDF 暂不支持文字识别。密钥配置、依赖目录、缓存和二进制文件会被跳过。单次最多 200 个文件，单文件不超过 2 MB，单次可入库文本不超过 10 MB。

**怎样保留自己的资料？**

`data/` 保存任务、材料、审核和面试记录，`runtime-config/` 保存模型配置。不要删除、覆盖或分享这两个目录。需要复制备份时，先停止应用，再完整复制两个目录到安全位置；备份也可能包含个人资料和密钥。

## 隐私与使用范围

- **本地保存不等于不出网**：审核与面试会把所需的材料片段、岗位信息和回答发送给你配置的模型服务商。上传前先脱敏，并确认资料允许发送。
- **分析不是事实认证**：报告与复盘用于整理证据和练习表达，不认证经历真实性或个人能力。模型可能判断错误，请结合引用原文自行核对。
- **只在本机使用**：没有多人账户和公网访问保护，不要直接把服务暴露到互联网。
- **不会代你操作外部平台**：不会自动读取 GitHub、执行项目代码、爬取招聘网站、发送邮件或投递简历。
- **分享前人工检查**：导出报告、截图、运行记录和备份可能含敏感信息，自动跳过或脱敏不能替代人工检查。
