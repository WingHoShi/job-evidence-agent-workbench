# 工作台使用指南

[返回项目首页](../README.md) · [运行与部署指南](deployment.md)

本文说明已部署工作台的业务操作。首次安装需先完成面试表初始化，再在网页配置自己的模型服务；步骤见部署指南。

## 工作台导航

界面面向桌面浏览器，最低布局宽度为 1024px。导航按业务阶段组织，未满足条件的阶段会显示锁定原因：

1. **任务概览**：材料数量、能力主张、待审核队列和下一步操作。
2. **材料中心**：批量文件、项目目录和粘贴文本导入，以及主张提取。
3. **证据审计**：横向滚动表格选择主张，详情面板展示候选证据、支持度、门禁与审核动作。
4. **审计报告**：完成全部主张审核后解锁，可生成并下载 Markdown 报告。
5. **模拟面试**：报告生成且至少接受一条主张后开始；默认综合模式，高级设置可调整练习参数。

## 材料导入

同一任务可以分多次导入简历、JD、多个项目目录或粘贴文本。支持 Markdown、TXT、DOCX、可复制文本 PDF，以及常见项目说明和源码文本，如 `pyproject.toml`、`package.json`、`Dockerfile`、`.py`、`.ts`、`.tsx`。

- 单次最多 200 个文件，单文件不超过 2 MB，单次可入库文本总量不超过 10 MB。
- 自动跳过 `.env`、`.git`、`node_modules`、虚拟环境、缓存、图片和其他二进制文件；目录导入只保存相对路径。
- 扫描件或不可复制文本的 PDF 会被拒绝，不提供 OCR；可改用可复制文本文件或粘贴内容。
- 跳过规则不能识别所有秘密。导入前仍需检查源码、说明和日志是否包含密钥或内部资料。

先体验时使用 [`examples/`](../examples/) 中完全虚构的简历、JD 和小型项目。`prompt-injection-demo` 刻意包含不可信材料指令；其中 `.env` 是虚构测试夹具，导入器会跳过，不要填入真实密钥。

## 逐条审计

1. 导入简历后点击“生成待审核主张”。系统仅从简历提取主张，不从项目文件新增经历。
2. 开始审核，点击“运行候选证据判定”。FTS5 BM25 + RRF 从项目材料和补充说明召回片段，简历和 JD 不作为能力证明进入候选。没有候选时直接返回没有证据，不调用模型。
3. 查看原文定位、模型理由、支持度和门禁。模型分析材料支持关系，确定性规则负责判断证据是否足够。
4. 人工接受或拒绝；接受未判定或有风险的主张需二次确认。**人工接受不改变支持度或门禁**。

充分支持必须引用项目材料；仅引用补充说明最多为部分支持，没有引用的支持结论会被后端降为没有证据。代码存在或项目中的重复自述不能单独证明材料真实、本人贡献或真实运行结果。

旧判定不会自动改写。对当前主张可点击“重新判定当前主张”，替换该条模型支持度和门禁，不改变人工审核状态。

误接受或误拒绝后，可选择该条主张，点击“撤销审核，返回待审核”并确认。系统保留材料、判定和历史记录，将该条放回审核位置，其余待审核条目继续排队。**已生成报告的任务暂不允许撤销审核**，避免报告与面试状态不一致。

## 报告与岗位对照

全部主张审核完成后生成报告，不额外调用模型。页面和 Markdown 导出按条保留人工接受/拒绝、证据支持度、风险、理由、门禁与引用定位，并提示需要补充的配置、日志或验证记录。拒绝的主张仍保留在报告中，但不计入已接受能力。

历史判定中的简历、JD、缺失或跨任务片段不作为报告证据展示，会标明历史引用风险；原判定和审核记录不改写。证据摘要最多展示 600 字，常见密钥字面量与 Windows 绝对路径会脱敏，但分享前仍需人工检查。

岗位覆盖是**关键词规则初筛**：保留岗位条目与定位，关联简历主张，区分已接受但待补证、仅有已拒绝主张、未关联与待人工分析。它不是语义匹配模型，不输出匹配率；未导入 JD 时会提示无法分析。

## 文字面试与复盘

### 练习参数

先生成报告，并至少人工接受一条主张。人工接受不代表主张已被事实验证，材料风险仍随主张进入面试上下文。

- 默认 5 题，高级设置支持 1–10 题、最多 5 项重点（每项 100 字）、5–120 分钟预计时长。
- 预计时长只是参考，不是倒计时；追问计入题数，有限题数不保证覆盖所有主张。
- 一次只展示一题；主问题后最多连续追问一次同主题，再轮转。程序限定话题和引用边界，模型生成自然语言问题。
- 每题回答最多 2,000 字，过程中不评分、不展示答案建议。末题答完进入待结束状态，需结束后生成整轮复盘。
- 提前结束需要确认，复盘标记部分完成；零回答不调用复盘模型，也不生成能力评价。

### 复盘与引用

复盘持久化逐题问题、原回答、有效信息、遗漏、技术解释、改进建议、总结和未覆盖主张。技术解释是模型分析，不是代码执行验证或招聘结论；面试回答不写入审计证据，也不改变人工审核结果。

逐题复盘可折叠，引用材料去重后集中展示。点击分析中的编号可定位并展开相应原文，便于对照结论。

开始面试时冻结材料上下文，只引用本任务合规项目/补充材料；简历和 JD 不能作为独立能力证据。旧版模板面试只读查看历史问题与回答；未保存的复盘不补造，新一轮需要主动开始。

### 模型调用与失败处理

正常完成 N 题约为 N 次出题调用 + 1 次复盘调用。每项生成操作最多两次 HTTP 请求，格式纠正与 JSON 模式回退共享预算。超时、鉴权、限流不会自动盲重发；手动重试可能额外计费，不能保证服务商只计费一次。usage 只记录服务商已返回的数值，可能不完整，不用于估算价格。

- 下一题失败时回答已经保存，只需重试生成；“刷新状态”是 GET，不调用模型。
- 网络失败时保留草稿与请求键；原内容可以直接重试。修改前先刷新确认是否已保存，已保存的回答不能覆盖。
- 同任务只允许一个未结束的新版会话；后端幂等校验不等于保证外部模型服务只执行一次。
- 出题/复盘输出上限分别为 1,000/6,000 Token，截断结果不保存为成功。按页面提示处理后显式重试，不用手工补括号冒充完整复盘。

上下文预算：每条主张最多 3 段证据，每段 1,200 字；JD 最多 4,000 字；出题输入最多 20,000 字，复盘输入最多 30,000 字。字符预算不是 Token 上限。缩减证据或早期历史会提示；必要信息仍超限时明确失败，不静默丢弃最新回答。

## 刷新与恢复

同一浏览器、同一地址刷新页面时，会打开最近任务的概览，并从后端快照恢复材料、主张、判定、门禁、审核状态与报告状态。审计进度依赖本机 `data/workflow.db`，不要只保留业务库而遗漏它。

面试题号、已提交问答和已保存复盘从后端恢复，进入页面不会自动调用模型。“再练一轮”进入准备页，不自动开始生成。

浏览器存储分别用于：

- `localStorage`：最近任务编号，不保存材料正文或 API Key；清除它不会删除后端任务。
- `sessionStorage`：按任务、会话、回合隔离的未提交面试草稿与请求键。关闭浏览器会话不保证草稿恢复；禁用存储时仅保留页面内存。

其他未提交表单不保证恢复。数据库、工作流与配置的备份、升级和回退方法见[部署指南](deployment.md)。

## 常见问题

- **停留在初始化页**：核对 Base URL、模型名称、权限与 API Key。测试连接和保存配置分别调用模型，可能计费；不是无费用的本地校验。
- **面试提示未初始化**：先按部署指南初始化面试表。应用不会自动迁移数据库，不要删除已有数据来解决。
- **模型判定失败**：区分鉴权、模型权限、限流/额度、超时与格式问题。失败不保存新结论或自动接受主张，可在当前主张上重试。
- **结构化输出不兼容**：审计需要 `verdict`、整数候选 ID 数组 `links` 和非空 `rationale`。明确不支持 JSON 模式时最多回退一次，仍严格校验结构和引用；格式失败最多纠正一次，两者共享两次请求预算。
- **导入文件被跳过**：检查敏感路径、依赖/二进制类型及大小限制；不要为了导入成功而去掉文件中的秘密检查。
- **刷新后没看到原任务**：先确认浏览器地址一致、后端挂载的仍是原数据目录；不要把新数据目录误认为原记录被删除。

## 隐私与费用

模型配置保存在 `runtime-config/model.env`，是本机明文秘密文件；初始化页和状态接口不回显密钥，不等于本机文件已加密。

审计与面试会发送选中的主张、材料、JD 和回答给用户指定的服务商。模型服务需要用户自己的 API 权限与额度，网页订阅或其他 Coding Plan 不保证通用。项目不自动执行导入的代码、不连接 GitHub、不发送邮件或投递简历。

导出报告、运行日志、数据库和备份也可能含隐私。演示只使用虚构资料，录制步骤见[演示流程](demo-script.md)。
