# 求职证据审计与模拟面试工作台 Demo 脚本

目标时长：3 到 4 分钟。演示时只使用 `examples/` 中的脱敏材料，画面中不要出现真实 API Key、简历、路径或聊天记录。

## 录制前准备

1. 使用独立验收目录启动：设置 `JOB_EVIDENCE_DATA_DIR=.acceptance-data` 和 `JOB_EVIDENCE_CONFIG_DIR=.acceptance-runtime-config` 后执行 `docker compose up --build`。
2. 打开 `http://127.0.0.1:8001`，在初始化页填写自己的 OpenAI 兼容模型配置，先测试连接，再保存。
3. 准备导入 `examples/resume.md`、`examples/jd.md`、`examples/projects/health-service/`。不要录入 `prompt-injection-demo/.env`。
4. 按 [部署交接](interview-v2-deployment.md) 初始化新版面试表。先在独立验收目录完成一轮真实模型检查再录制，模型调用存在费用；本轮自动测试并未代替这一步。

## 讲解顺序

### 1. 开场：项目定位（20 秒）

“这是一个单机部署的求职证据审计与模拟面试工作台。它不替用户编造经历，而是核验简历中已经写出的能力主张是否有项目材料支持。”

展示初始化完成后的工作台和本地运行地址。

### 2. 导入材料与边界（35 秒）

创建“AI 应用开发岗位演示”任务，分别导入脱敏简历、JD 和 `health-service` 项目目录。

“系统支持批量文件、粘贴文本和浏览器选择的项目目录。导入器会自动跳过 `.env`、`.git`、依赖目录和二进制文件，并且只保存相对路径。”

### 3. 主张与证据审核（70 秒）

点击“生成待审核主张”，然后开始逐条审核。选中 FastAPI 主张并点击“运行候选证据判定”。

“候选证据通过 SQLite FTS5 的 BM25 与 RRF 融合召回。模型只能看到当前主张和候选片段；系统再用确定性门禁判断证据是否足够，避免把代码存在误认为本人负责。”

展示候选证据、支持程度、门禁结果和执行轨迹。接受一条主张；对无证据或冲突主张选择拒绝或补证。

### 4. 报告与模拟面试（70 秒）

完成审核后生成报告，展示“已确认”“材料不足”等分类与 Markdown 导出入口。

“报告只使用人工确认后的结论。接下来可启动文字模拟面试：系统一次只问一题，根据回答追问，结束后才统一生成复盘，避免边答边评分造成干扰。”

演示时用高级设置选 2 题（含追问）。先回答你确实实现的接口逻辑，再展示围绕该回答的同主题追问；第二题回答后结束，展示逐题原文、遗漏、技术分析与行动建议。可提前结束，但需保留“部分完成”提示，不剪成完整一轮。

刷新页面再进入面试，展示恢复的复盘；点击“再练一轮”只进入准备页，不自动调用模型。若生成失败，展示“回答已保存”与显式重试，不重新提交已保存答案，不把失败剪辑成成功。真实模型应检查是否一个聚焦问题、是否基于回答追问、是否乱认个人贡献；结构化测试无法保证这些语义质量。

### 5. 收尾：恢复与安全（20 秒）

“审核与面试状态保存在本地 SQLite，刷新后可以继续；面试回答不改变审计证据。模型 Key 不回显，但选中的材料和回答会发送给用户配置的模型服务商，因此演示必须脱敏。系统不自动读取 GitHub、不执行项目代码、不自动投递。”

## 录制检查

- 页面中没有 API Key、真实姓名、联系方式或真实项目路径。
- 画面展示了材料导入、候选证据、门禁、报告和一次文字问答。
- 浏览器缩放为 100%，文字清晰；录制文件保存到项目外或被 Git 忽略的目录。
